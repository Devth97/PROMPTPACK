AI Carousel Prompt Template for Six Connected Slides

A useful carousel prompt gives each slide a different job while keeping one visual system across the set. Define the reader, the central idea, source notes, slide order and next action before requesting images. Review the cover at phone size, then carry the same typography, palette and image direction into the interiors.

By PromptPack · Reviewed 28 October 2026

Copy the templateWorked exampleUse and review itChoose your next step

What do you need?

A text assistant, an image tool or design editor, source notes and time to review each slide. Generation credits and publishing accounts are separate.

Copy and customize this prompt

Replace each bracketed field. Keep unknown facts marked as missing so they can be resolved before production.

Plan a six-slide carousel for [AUDIENCE] about [ONE QUESTION].
Use only these source notes: [VERIFIED FACTS AND LINKS]. Mark gaps explicitly.
Reader takeaway: [ONE USEFUL IDEA]. Next action: [ONE ACTION].
Slide jobs: 1 cover promise; 2 context; 3 explanation; 4 worked example; 5 practical check; 6 takeaway and next action.
Define one visual system: [CANVAS], safe margins, palette roles, type hierarchy, image medium and page markers.
For each slide return a headline, short body, image direction, source note and suggested alt text.
Keep the visual system consistent and let the content determine each layout.
Separate fictional examples from sourced facts. Do not invent studies, quotes or engagement results.
Before generating images, flag dense text, repeated slide jobs and an unsupported cover promise.

Worked example: inputs, outputs and revisions

We filled the template with a sourced topic: how to choose alt text, using the W3C WAI alt decision tree. The plan came from the template; the slides were then laid out in HTML and CSS and exported as images. No image generator was used.

How it was run: Generated on 28 October 2026 in a Claude Code session by Claude Opus 5.5 (model ID claude-opus-5-5). Slides composed in HTML/CSS with the Figtree font and exported at 1080 × 1350 px with headless Chrome. W3C sources checked on the same day. Cost was not measured.

Input: the filled template

Plan a six-slide carousel for small business owners who edit their own website about one question: what should the alt text say for each image?
Use only these source notes: W3C WAI "An alt Decision Tree" (https://www.w3.org/WAI/tutorials/images/decision-tree/, updated 13 May 2024). Decorative image or text repeated nearby: empty alt. Image inside a link or button: say where it goes or what it does. Simple image that adds meaning: a brief description of that meaning. Graph or complex image: put the information elsewhere on the page. Image of text not shown elsewhere: include that text. Mark gaps explicitly.
Reader takeaway: decide what the image does before writing its alt text. Next action: check the images on your own homepage with the decision tree.
Slide jobs: 1 cover promise; 2 context; 3 explanation; 4 worked example; 5 practical check; 6 takeaway and next action.
Define one visual system: 1080 x 1350 canvas, 80 px safe margins, palette roles (cream #FFFBF2 background, ink #0B0B0F text, pink #F598F2 slide marker, yellow #FFE14D highlight), Figtree headlines at weight 800 and body at 500, flat shapes instead of photographs, page markers "n / 6".
For each slide return a headline, short body, image direction, source note and suggested alt text.
Keep the visual system consistent and let the content determine each layout.
Separate fictional examples from sourced facts. Do not invent studies, quotes or engagement results.
Before generating images, flag dense text, repeated slide jobs and an unsupported cover promise.

What the review found

  • The plan flagged two of its own lines before any design work: slide 2 cited no source for how screen readers use alt text, and slide 5 promised a check “in ten minutes”, which nobody had measured.
  • Both were resolved before design (see the plan revisions): slide 2 now cites two WAI pages and slide 5 drops the time claim.
  • Viewed at phone size, the first layout of slide 4 had its label colliding with the page marker, and the alt text lines, the point of the example, were the smallest text in the set.
  • The source lines on slides 2, 3 and 6 were about 9 px tall at phone size, which breaks the template’s own advice to keep sources legible.

Limitations of this example

  • The source lines are still small on a phone. A caption with the links is the better place for full citations.
  • The carousel was not posted, so there are no reach or engagement figures.
  • Laying out slides in HTML needs some CSS knowledge; a design editor gives the same control over exact text. If you use an image generator, check every word it renders.
  • Slide alt text in the plan is a draft for review, not a finished description.

How do you plan six slides without repeating yourself?

Write the takeaway first, then assign a job to each slide. If two slides only restate the same claim, combine them and use the space for an explanation or example. The cover creates an expectation; the interiors should deliver on it. End with a relevant action instead of an unrelated follow request.

For a fictional desk-lighting checklist, the set could move from a clear question to a description of the workspace, a demonstration of where shadows appear, an illustrative before/after layout, a practical check and a final reminder. Label that staging as an example and avoid inventing measured improvements.

How do you keep generated slides visually consistent?

Create the style block once. State the role of each color, the headline and body hierarchy, the image medium, margins and recurring markers. Repeat those decisions when briefing each slide. Generate or compose the cover first and inspect it at phone size before producing the whole set.

Consistency does not mean six identical layouts. Keep the type and image treatment recognizable while varying the composition to fit the slide's job. Use a design editor when a generation tool cannot reliably place exact text.

What belongs in the production handoff?

  1. Approved slide order and exact copy.
  2. Final images with predictable file names.
  3. Source links for factual claims and labels for fictional examples.
  4. A caption, suggested alt text and the next-action destination.
  5. An owner and revision so the right files are approved.

Image creation and publishing are separate steps. Review the exact exported files before posting. If you later connect a publishing tool, use the platform's current documented route and confirm account requirements.

How do you review readability and accessibility?

  • Read every headline on a phone-sized preview.
  • Check text contrast, margins and line breaks across the whole set.
  • Keep factual source notes legible rather than shrinking them into decoration.
  • Write alt text that communicates the meaningful content and image context.
  • Check that the caption adds context and does not contradict the slides.

Alt text is a starting draft to review, not a place to repeat search keywords. Assess real post results before changing the next brief. The template supplies a process, not a promised reach or engagement rate.

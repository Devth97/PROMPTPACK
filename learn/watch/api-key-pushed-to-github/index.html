API Key Pushed to GitHub? Rotate It First

Make a new key and revoke the old one at the provider straight away; deleting the file is not enough because Git keeps history and public repositories are scanned for keys. Then check the provider’s usage page for activity you did not cause, move keys into a .env file that Git ignores, and turn on secret scanning.

By PromptPack · Reviewed 28 October 2026

What should you do, step by step?

  1. Revoke and replace the key. In the provider’s dashboard, create a new key and revoke the leaked one. Do this before cleaning up the repository.
  2. Update what used the old key. Put the new key in your app’s environment settings or secret store and redeploy. Anything still using the old key will stop working.
  3. Check for misuse. Review the provider’s usage, billing and audit logs for activity you did not cause, and contact the provider if you find any.
  4. Clean up the code. Remove the key from the code. Rewriting Git history can remove old copies, but treat the key as exposed either way.
  5. Prevent the repeat. Keep keys in a .env file listed in .gitignore, and turn on GitHub secret scanning and push protection where available.

General steps; each provider’s dashboard differs. Rotation stops future misuse of the old key but does not undo anything already done with it. See GitHub Docs: secret scanning.
